## Active disproof / classification

The strongest counter-explanation would be that `OnBordUnit` is a valid alternate German device-class label or executable spelling. The official original German §1.4 (V1.0–2.1) and §1.3 (GC2.2–2.4) explicitly call these **XML enumeration terms**; five independent original English versions print `OnBoardUnit`, all four exact prior official Enumerations XSDs and the explicitly selected V2.4 candidate match English; V2.2/2.3/2.4 German glossaries repeat the misspelling. Therefore this is a **confirmed long-lived official PDF/documentation typo** and misleading identifier, not an executable alias.

The first available publication is **already affected**. There is **no earlier published nonaffected predecessor in the pinned 301-2 source registry** and **no corrected release through the latest checked GC V2.4**. The V1.0 exact source is German-only, so there is no invented English V1.0 PDF counterexample.

**Provider/SDK rule:** the selected **official** historical XSD (V1.0–V2.2) is the exact normative XML authority: `OnBordUnit` **FAIL**, `OnBoardUnit` satisfies this enum condition. This must not be waived, translated or normalized. An explanatory known-issue diagnostic may accompany the XSD failure.
