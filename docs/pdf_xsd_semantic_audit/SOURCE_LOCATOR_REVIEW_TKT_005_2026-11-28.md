## Executable authority and active falsification

The complete original aggregate global element at line 131 and later service at line 77 map TicketingService.GetValidationResult to TicketingService.GetValidationResultResponseStructure. Original service lines 108–119 and later lines 78–89 independently define an outer required choice and an inner required sequence. TicketingService.ValidationResultStructure is absent, not a historical alias or an abbreviation of the inner type. The correct payload can take either ValidationResultData (TimeStamp and ValidationResult) or OperationErrorMessage. The explicit nonexistent overview type fails SCHEMAV_CVC_ELT_4_2; the existing but unrelated inner type is not derived from the outer type and fails SCHEMAV_CVC_ELT_4_3. The isolated original service has no corresponding global root; do not confuse packaging failure with type rejection. No synthesized root or type, no alias, no normalization.

The strongest counterargument is a historical type or merely line-wrapped shorthand. Both visible overviews contain the full wrong name; exact named-type inventories in both historical profiles and targeted execution disprove interchangeability. The visible detail tables EN123 and DE9 identify the outer choice and refer to the inner type, while EN124 and DE10 list inner fields under a misleading label. The latter is TKT-007, independently pending; this block does not close it. Table labels and +Structure notation are not normative global root names.
