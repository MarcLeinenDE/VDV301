## Fresh-reading conclusions

The fresh read independently confirms the existing architecture interpretation:

- Part 1 defines the IBIS-IP architecture; Part 2 defines the technical XML interfaces.
- the former IBIS master/slave concept is replaced by a service-oriented architecture;
- service and operation identity are architectural concepts independent of a specific physical device;
- every vehicle is treated as its own IBIS-IP system boundary;
- the document limits the presented architecture to non-safety-related systems and gives only architectural security requirements, not a concrete TLS/cipher/certificate profile;
- rapidly changing information is associated with UDP/multicast suitability, while reliable communication is associated with TCP/HTTP;
- XML is the service information exchange format and Part 2 supplies the technical structures;
- SNTP and RTP are named as conceivable additional protocols but are explicitly not specified in this 01/2014 edition; later VDV publications may and do refine those areas.

No existing ARCH-001..ARCH-008 conclusion from the first pass was contradicted by the fresh reading.

## New/strengthened audit candidates

### DR3011-001 — wrong internal cross-reference for System-Management

Classification candidate: `pdf_cross_reference_error_candidate`
Confidence: high from native text; visual page confirmation still pending.

The document's table of contents and section headings define:

- 5.1.2 = System-Dokumentation
- 5.1.3 = System-Management

In the example introducing `SystemManagementService`, however, the text calls it an implementation of the System-Management functional component and refers to `5.1.2`.

This is internally inconsistent. The intended reference is very likely 5.1.3.

No XSD change follows from this finding.

### DR3011-002 — architecture example operation names vs V1.0 SystemManagement XSD

Classification candidate: `cross_document_operation_name_mismatch_candidate`
Status: pending fresh VDV 301-2 V1.0 deep-read cross-check.
Confidence: medium/high as a mismatch observation; root cause not yet classified.

The Part 1 example names operations such as:

- `GetDeviceState`
- `GetSystemStatus`
- `SubscribeDeviceStatus`
- `SubscribeSystemStatus`
- corresponding unsubscribe names.

The selected historical V1.0 `IBIS-IP_SystemManagementService_V1.0.xsd` instead exposes the global response roots:

- `SystemManagementService.GetDeviceStatusResponse`
- `SystemManagementService.GetServiceStatusResponse`

and its service group contains those response names.

This may reflect conceptual/pre-final terminology in the architecture document rather than an XSD defect. Do not classify or remediate until the fresh VDV 301-2 V1.0 deep read establishes the service-publication terminology and historical context.

### DR3011-003 — duplicate `IBIS-IP` abbreviation entry

Classification candidate: `minor_pdf_editorial_duplicate_candidate`
